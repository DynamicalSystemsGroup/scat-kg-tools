# Variant C: edges as a block on the narrative

**Rule.** Nodes and narratives are pages. Each narrative holds a table, `Edges told`: one row per edge it tells (type, from, to, note). The relationship annotation is a line on one of its two entries. Each folder has an index page (`concern/concern.md`) holding a Search query, `[type:concern]`. An edge has no status of its own.

**Recording an edge.** Add a row on the narrative that tells it, with both ends as links. A second narrative telling the pair adds its own row: held twice (two pairs here).

**Reviewing.** The table is the narrative's edges. Its nodes are its outgoing links, which include the table's.

**Mismatches expected.**
- A row's ends are links, so a narrative cannot name an edge and miss an end. `night-main-break` links treatment-operators and low-operating-cost only through its table, not its account.
- `night-main-break` links both ends of two minimal-service-interruptions edges without a row.
- `dry-july-allocation-talk` links both ends of environmental-flow-protection to river-flow-display, which has a row only in `sensor-first-pitch`.
- `sensor-first-pitch`: none.

They show as a linked pair with no row in `Edges told`, or an account lacking a link that a row has.
