# Stack A (pyoxigraph + SPARQL) results

Rules are SPARQL queries over a pyoxigraph store (`checks.py`: `Q_FIELD`, `Q_CLASS`, `Q_LINK`); required fields and endpoint
classes are read from the placeholder TBox in the store, not hard-coded. Rule ids: `SPK-FIELD-REQUIRED`,
`SPK-ENDPOINT-CLASS`, `SPK-LINK-MISSING`. Run everything from `research/toolchain/spike/`.
Scope: local = one page; neighborhood = page + pages it links to + pages linking to it (computed in SPARQL, in the timed
query); full = whole vault. Missing required fields are errors at every status (R-3 strictness is not implemented; spike).

## What is timed

- **query only**: `run_check(store, scope, page)` on an already-built store. This is what a long-lived process (REPL) pays per check.
- **load**: `parse` (read files with `common.parse_vault`) and `build` (RDF triples into pyoxigraph, TBox included).
- **load + query**: parse + build of the whole 500-page vault, then one check. This is what a fresh CLI call pays. Local and
  neighborhood still load the whole vault, because endpoint classes and backlinks need other pages. A scoped load was not tried.
- Cold = run 1 of 7 in a fresh process (first query use); warm = runs 2-7 (median, min, max). Vault files were just written, so
  they sit in the OS file cache in all runs (no true cold-disk run).
- The page used for local/neighborhood is the highest-degree page in the generated vault (worst case).
