## Purpose

In the inference.coop run the server held every rule (no `done`, no hand-written row, no page body reached the vault),
but the assistant's words did not: it reported things that were not so, decided what the coder decides, declined for the
wrong reason, and drafted carelessly. The chief engineer asked for the probes "to gather evidence about how it works now
so you can better define the fixes and tests to ensure the behavior is corrected". The probes P1 to P8 and V1 to V3 and
their findings are in `work-packages/WP28-WP30-inputs.md`. Words follow `GLOSSARY.md`.

## Goals

- **WP30-G1. True reports.** The assistant states only what a tool returned, and calls `status` (or the view it is
  describing) before describing the vault.
- **WP30-G2. The coder decides.** It proposes nodes, edges and duplicates and waits for the coder's yes before it
  records; duplicates go through `review` or a merge plan; choices it hands back say what each does and who acts
  (the chief engineer: the "what would happen" column "needs ... filled in").
- **WP30-G3. Declining by role.** When a rule stops it, it says whose act that is (the coder's, or the setup person's for
  a setting), never that a capability is missing, and it does not try the chat's own file tools on the vault.
- **WP30-G4. Careful drafts.** A drafted account follows the template's narrative form, takes facts from the notes only,
  and writes links that resolve; it never tells the coder to hand-write a table row.
- **WP30-G5. The probes as the acceptance test.** P1 to P8 and V1 to V3 become a written test plan with an oracle per
  probe, run on inference.coop and Claude after the change, and compared with the 27 November baseline.

## Non-goals

- Server-side enforcement beyond today's (it already held every rule).
- The guides (WP29) and the drawings (WP28); WP30 points to them.
- Choosing or recommending a model for a provider.

## Contracts

## Definition of good enough

WP30-R1 to R5 met, and *(open decision, see below)* which providers must pass the G1 and G2 probes with no failure.

## Open decisions

- **The pass bar's providers.** Options: (a) Claude, the chatbot path's worked example, must pass; inference.coop's
  results are recorded and dispositioned; (b) both Claude and inference.coop's default model must pass.

## Definition of good

On every provider tried, the assistant tells the truth about the vault, leaves every interpretive call to the coder, and
drafts text the coder can paste as it stands.

## Agent's defaults

- *(default)* The probes run human-paced, one message at a time, on the lab vault, with the chief engineer's sign-ins.
- *(default)* The plan adds a probe for each habit the baseline did not cover (for example, options with their effects).
- *(default)* A model that fails a probe on a habit the rules state clearly is recorded, not worked around in the rules.
