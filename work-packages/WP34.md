## Purpose

Reading the figures as a coder (`acceptance/walkthroughs/analysis-in-practice.md`): node pages that no row tells appear
in no figure (the fridge's `whiteboard` page), and candidate links (named in the text, no row) are drawn dashed only in
a fingerprint (`draw.fingerprint(..., candidates=True)`, built in WP17), not in the layered view, so the whole-vault
picture hides what is left to code.

## Goals

- **WP34-G1. Orphan pages.** The layered query's result lists the node pages no row tells (with their type and status),
  so both renderings carry them (WP33): the table lists them and the plot names them beside the figure.
- **WP34-G2. Candidates in the layered view.** The layered query takes `candidates`, as the fingerprint does; the plot
  draws candidate links dashed and the table lists them.
- **WP34-G3. Candidates where there is no account.** When a narrative has no account text, its only links are its rows,
  so every adjacent pair is a candidate and the candidates say nothing about the text. The query result says so for
  that narrative, and both renderings show it (the plot's footer, a line in the table). Found in the Claude loop run
  (`acceptance/walkthroughs/mvc-loop-claude.md`).

## Non-goals

- Changing what a candidate is (rule 4) or the fingerprint's candidates (they exist).
- Layout (WP35). Deleting or merging orphans (the coder decides, with `review`).

## Contracts

The layered query's result gains `candidates`, the orphan list and the no-account flag (and the fingerprint's result
gains the flag); the machine-interface schema follows, additively; the CLI, API and the server's `layered` tool gain
the option (WP33 has retired `draw_layered`).

## Definition of good enough

WP34-R1 to R4 met.

## Definition of good

The whole-vault picture and its table show the coder both what is coded and what is left to code, and never present
candidates as evidence when there is no account to draw them from.

## Agent's defaults

- *(default)* Orphans are listed in the drawing's footer, at most ten names, then "and N more".
- *(default)* `candidates` defaults to false, as in the fingerprint.
