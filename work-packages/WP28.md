## Purpose

The analysis stage needs pictures a coder can read, made by the tools and interpreted by the assistant. WP17 built the
drawings (`scat_kg.draw.fingerprint`, `draw.layered`, with `.png()` and `.svg()`) "as images the notebook shows and the
MCP server can return later"; no package took up "later" (`work-packages/WP28-WP30-inputs.md`). In the inference.coop
run the assistant wrote Mermaid itself. The chief engineer (D-160): "i don't want you to be authoring mermaid manually.
i want the tools to generate and return svg or png", and he asked after "the finger print plots, the layered graph or
the traces". Words follow `GLOSSARY.md`.

## Goals

- **WP28-G1. The server draws.** Tools that return the fingerprint, the layered view and a trace as images, made by the
  `draw` module (the same code as `scat draw` and the notebook), not by the model.
- **WP28-G2. A trace drawing.** `draw.trace(...)`, in the same four-column layer order, with its CLI and API twins.
- **WP28-G3. The server's image has what it needs.** The container installs the `draw` extra.
- **WP28-G4. Seen on screen.** The images are checked in Claude and in inference.coop, each reported as shown or not.

## Non-goals

- New kinds of view, or changes to what a view contains (the data stays WP17's).
- The assistant's wording about images (WP30) and the lifecycle guide for the analysis stage (WP29).
- Interactive or animated drawings.

## Contracts

The MCP interface gains the drawing tools (`docs/reference/mcp.md`); the machine-interface schema gains the trace
drawing beside `draw`. Existing tools, fields and schema versions do not change.

## Definition of good enough

WP28-R1 to R6 met. If a chat does not show a returned image, the record says so and the docs say what that chat's user
does instead.

## Definition of good

Asked for a picture, the assistant calls a tool and the coder sees the same drawing the notebook would show.

## Agent's defaults

- *(default)* PNG is returned as image content (the MCP SDK's `Image`); SVG is offered as an option of the same tool.
- *(default)* One tool per view (`draw_fingerprint`, `draw_layered`, `draw_trace`), mirroring the view tools.
- *(default)* The server's drawings are never written to the vault; saving a file stays `scat draw --out`.
- *(default)* The on-screen check of R5 runs with the chief engineer's accounts and keys; the ACE plays the coder in
  the chat (his rule for chat-app runs, in WP30).
- *(default)* The same check tries Claude with both header forms (`authorization: Bearer <key>` and `x-api-key`), since
  why the first failed on 27 November is not known, and the chat path's page keeps the form that works.
