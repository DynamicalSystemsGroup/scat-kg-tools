## Purpose

Give the coder and the analyst the views of `MISSION.md` G12, built once in the tool and shown by the notebook (and,
in WP18, by the MCP server): the fingerprint view, the edge tables, the layered view and traces. Words follow
`GLOSSARY.md`; modules follow `contracts/architecture.md` (M1 loader, M6 view generator, M9 notebook, M10 template).

## Goals

- **WP17-G1. The view generator (M6)** in `scat-kg`: from a conformant knowledge graph, the data of each view:
  a narrative's fingerprint (its nodes and edges, plus the rule-4 candidates, D-085); the three edge tables; the
  layered view's nodes and edges for a chosen set of narratives or the whole vault; and traces up and down the
  layers from any node. Each view is data first (with its machine-interface form, R-16) and only then a drawing.
  Relationship annotations are left out of every view.
- **WP17-G2. Exports**: each edge table as CSV, and a generated Markdown document per edge table, written only by an
  explicit operation (R-4), with REPL and CLI twins (R-8).
- **WP17-G3. Drawings**: the fingerprint view and the layered view drawn as four columns in layer order, as images
  the notebook shows and the MCP server can return later.
- **WP17-G4. The template notebook (M9)**, in `scat-kg-template`: loads the vault through the public loader, shows
  each view with one short paragraph of plain words, and runs top to bottom in the template's CI (R-17).
- **WP17-G5. Docs**: a short analysis guide (J9) and the API and CLI references for the new calls.
- **WP17-G6. Carried from WP16 (D-091)**: the flow page's "Two readers" heading follows the one persona; step 7's
  dependency names step 4; the stray `conflicts` comment in `ontology/scat.ttl`.

## Non-goals

- Network measures beyond the four views (G12; the mission's non-goal on analysis tooling).
- Any change to what the graph means.

**Design (the contract every unit fits).** Words follow `GLOSSARY.md`. Nothing below changes what the graph means.
- **Loader.** `scat_kg.load(root=".")` is the public M1 loader: `scat_kg.graph.load`, exported (already built).
- **Views (M6)**, module `scat_kg/views.py`, each exported from `scat_kg` and returning a `View` (or a refusal
  `Result`): `fingerprint(narrative=None)`, `edge_table(type)`, `layered(narratives=None)`, `trace(node, direction="both")`,
  all with `root=`. `View.ok`, `str(view)` (the text), `to_dict()` (the document). Deterministic: layer order, then
  name; the same vault gives the same bytes.
  - `fingerprint`: one narrative by name, or every narrative (path order) when none is given.
  - `edge_table(type)`: `type` one of the TBox's edge slugs (`holds`, `addressed-by`, `provided-by`).
  - `layered(narratives)`: the union of the fingerprints of the named narratives; none given means every narrative
    of the vault. Nodes are those the fingerprints link; edges are those their rows tell; no candidates.
  - `trace(node, direction)`: `up` (toward groups), `down` (toward technologies) or `both`; reachable by edges that
    keep one direction; the start node is not in its own result.
- **Document** (`kind` is `view`; `operation` is `fingerprint`, `edges`, `layered` or `trace`; `schema_version` stays
  2: a new document kind and new command names are not in the closed lists the contract names). A node is
  `{name, type, status}` (`type` is the layer; `status` as written). An edge is `{type, from, to, narratives, status}`:
  the graph's edge, with every narrative that tells it and its derived status, in every view. A candidate is
  `{type, from, to}` (rule 4, D-085). `fingerprint`: `narratives: [{name, kind, status, nodes, edges, candidates}]`
  (`nodes` flat, in layer order; the narrative's own rows are its edges). `edges`: `edge_type`, `from_layer`,
  `to_layer`, `rows` (edges, in graph order). `layered`: `narratives` (the names drawn), `nodes` (an object keyed by
  layer, in layer order), `edges`. `trace`: `node`, `direction`, `up`, `down` (nodes in layer order then name; `[]`
  for a direction not asked), `edges` (the edges walked). Relationship annotations appear nowhere.
- **Refusal.** A view refuses (kind `operation`, `ok` false, the existing refusal and `problems` shape; no new rule id) on
  an unknown or ambiguous name, an unknown edge type or direction, a missing vault folder, and on any **error** in the
  pages it draws: the narratives it names or shows, and the node pages in its result (warnings do not refuse).
  The refusal carries those problems with their fixes, as data.
- **Exports** (`scat_kg/export.py`), explicit operations returning a `Result`: `export_edges(out, *, root)` writes, for
  each edge type, `<out>/<slug>.csv` (header `from,to,narratives,status`; narratives joined by `;`; UTF-8, LF,
  deterministic) and `<out>/<slug>.md` (a generated heading, one sentence, a table; names are plain text, never
  `[[links]]`, so no page, link or row is made in a vault). `out` is required (no hidden default). A file that
  exists is overwritten only when its content differs (`unchanged` otherwise); repeating changes nothing. The
  folder is made if absent. If `out` is inside the vault, `scat check` output is unchanged.
- **Drawings** (`scat_kg/draw.py`, optional extra `draw` = matplotlib): `draw.fingerprint(narrative)`,
  `draw.layered(narratives=None)`, each with `root=`, return a `Drawing` (or the same refusal as the view; or a
  refusal naming `pip install "scat-kg[draw]"` when matplotlib is absent). Four columns in layer order, labelled,
  edges between neighbouring columns, drawn from the view's data and never from the graph again; nothing on a
  drawing orders by a measure. `Drawing.png()` and `.svg()` return bytes and text; `_repr_png_` shows it in
  Jupyter; `Drawing.save(path)` is its explicit write. Output is deterministic (fixed fonts and seeds, no dates).
- **CLI twins** (`cli.py`): `scat fingerprint [NARRATIVE]`, `scat edges TYPE`, `scat layered [--narrative N ...]`,
  `scat trace NODE [--direction up|down|both]`, `scat export-edges --out DIR`, `scat draw fingerprint|layered ... --out FILE`;
  each takes `--root` and `--json`, prints `str(result)`, and its `--json` equals `to_dict()`.
- **Tests** (R-2, R-3): a small vault under `tests/views/` whose every view is computed by hand in the test (a narrative
  with no edges, one disconnected fingerprint, one rule-4 candidate, an edge told twice); views write nothing (tree
  hash before and after); REPL equals CLI; every document validates against the schema.
- **Operating notes for the chat path:** none; WP17 does not touch it (M8 is WP18).
