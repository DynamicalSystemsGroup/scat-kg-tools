## Purpose

Give the coder and the analyst the views of `MISSION.md` G12, built once in the tool and shown by the notebook (and,
in WP18, by the MCP server): the fingerprint view, the edge tables, the layered view and traces. Words follow
`GLOSSARY.md`; modules follow `contracts/architecture.md` (M1 loader, M6 view generator, M9 notebook, M10 template).

## Goals

- **WP17-G1. The view generator (M6)** in `scat-kg`: from a conformant knowledge graph, the data of each view:
  a narrative's fingerprint (its nodes and edges, plus the rule-4 candidates, D-085); the three edge tables; the
  layered view's nodes and edges for a chosen set of narratives or the whole vault; and traces up and down the
  layers from any node. Each view is data first (with its machine-interface form, R-16) and only then a drawing.
  Relationship annotations are left out of every view.
- **WP17-G2. Exports**: each edge table as CSV, and a generated Markdown document per edge table, written only by an
  explicit operation (R-4), with REPL and CLI twins (R-8).
- **WP17-G3. Drawings**: the fingerprint view and the layered view drawn as four columns in layer order, as images
  the notebook shows and the MCP server can return later.
- **WP17-G4. The template notebook (M9)**, in `scat-kg-template`: loads the vault through the public loader, shows
  each view with one short paragraph of plain words, and runs top to bottom in the template's CI (R-17).
- **WP17-G5. Docs**: a short analysis guide (J9) and the API and CLI references for the new calls.
- **WP17-G6. Carried from WP16 (D-091)**: the flow page's "Two readers" heading follows the one persona; step 7's
  dependency names step 4; the stray `conflicts` comment in `ontology/scat.ttl`.

## Non-goals

- The MCP server and the chat path (WP18); the range vault (WP19).
- Network measures beyond the four views (G12; the mission's non-goal on analysis tooling).
- Any change to what the graph means.

it without knowing the ontology.
