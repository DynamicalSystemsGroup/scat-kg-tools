## Purpose

In the inference.coop run the group cap (3, already full) stopped a coder on the chat path: the tool refused, the
assistant could not change `scat.toml`, and no page told a coder who works without a terminal how to go on. The chief
engineer (D-159): "setup person's job + loosen the default cap to 6". Words follow `GLOSSARY.md`.

## Goals

- **WP27-G1. A looser default.** The template ships `stakeholder_group_cap = 6`.
- **WP27-G2. Settings are the setup person's job.** The pages say a vault setting (the cap, the attribution mode) is
  changed by whoever set the tools up; Planning tells the organiser to settle both with that person before the first
  session; the chat path says where to turn when the tool refuses for a setting.
- **WP27-G3. Nothing still says 3 as the default.** Every page, example and test that states the template's cap as 3 is
  brought in line, or keeps 3 where it is an example's own value and says so.

## Non-goals

- A tool that writes `scat.toml`, through the CLI, the API or the server. The assistant still cannot change settings.
- Changing what the cap rule checks, or its message's operation or fields (R-22).
- The attribution modes themselves (WP23).

## Contracts

`contracts/rule-catalogue.md` and the page contracts change only where they state the template's default value.
