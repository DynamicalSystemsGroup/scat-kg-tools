## Purpose

Bring the release up to what the chat path's live run taught (`acceptance/chat-path/live-run-wp18-r4.md`, candidates
C1 to C8 in `work-packages/candidates.md`, all in v0.1 by D-102 and D-103). Separate the tool's **rules** (what
conformance requires, enforced by the tool) from the **norms** (guidance for coders and assistants, the same for a
person or an LLM, carried in docs and skill files). Make the chat path's session life cycle reproducible and secure,
with the stricter "leave no trace" life cycle shown as one option. Words follow `GLOSSARY.md`.

## Goals

- **WP21-G1. The edge table reads subject, predicate, object (C1).** The "Edges told" table's columns are
  `from | type | to | note`; each row reads as a sentence ("parents holds bike-safe-for-children"); every edge name
  reads in that direction. A skimmability requirement is stated in the layout contract.
- **WP21-G2. Uncoded narratives are excluded, and say so (C2, the rule).** A narrative with no declared node is left out
  of the graph and the views by the tool and is marked excluded where the tool reports on it; it is included once it
  declares a node. A lone node (no edge) has one conformant place to be declared.
- **WP21-G3. The norms, apart from the rules (C2 to C5).** One normative guide, separate from the rule catalogue:
  coded narratives (the expected shape: a coherent account and a set of nodes and edges, not necessarily connected,
  their worth in recurrence across narratives); links in the account text (a "may"); descriptions (brief, not
  repeating the account; the `done` error is intended; an assistant may offer one); writing as a mixed loop, either
  side first, any number of rounds, with the coder's `done` as validation; status set when the coder leaves a page
  (`done` or `draft`; nothing forces `draft`); and the fields `done` needs, shown to a coder finishing in one sitting.
- **WP21-G4. The norms as chat-path skill files (C6).** The assistant's rules and the norms ship as skill files in the
  tools repo (a SKILL.md package), including the edge grammar, `kind`, one loop step per reply, offering a
  description, and naming pages to tag at the end of a session. The chat-path guide uses the chat's Skills and a saved
  agent, and says how to start a chat with the agent.
- **WP21-G5. The session key is handled as a secret (C7).** A spike picks the secret handling on macOS (for example
  the login keychain) so the key is never in a process's arguments or a world-readable file and is on the clipboard
  only when the coder asks; the launcher is changed to it; the life-cycle walkthrough describes good security practice.
- **WP21-G6. The published image; Colima the default (D-105, D-106).** CI builds the MCP server's image and publishes
  it at each release; the launcher pulls the image for its version instead of building it. The chat-path guide leads
  with Colima (v0.1 is Mac only); Docker Desktop is the untested alternative.
- **WP21-G7. The life cycle, and "leave no trace" as an option (C8, D-107).** The chat-path guide walks a session from
  start to clean-up. A separate walkthrough shows the "leave no trace" option for a strict data policy (an AI-platform
  non-retention or "approved chatbot only" policy): a temporary chat, the field notes uploaded as a collection, the
  server entry, agents, prompts and skills set up for the session, and every one of them removed from the platform at
  the end, local copies kept. It says plainly that this is one policy option, a MAY, not a recommendation.
- **WP21-G8. WP8-U1, carried (D-110).** The held fixes (`wp8/u1`: stub on an existing page of the same type is a
  no-op; `set-status done` reports the page's own check) ported onto `dev`, with exactly the two assertion changes
  D-110 allows in `tests/ops/test_ops_stub.py`.

## Non-goals

- The live runs of the chat path (G7's walkthrough run, the chat-path UA-A): the chief engineer's sittings, as he
  pastes each key.
- Docker Desktop testing (withdrawn, D-105). Any platform but macOS.
- Making "leave no trace" a default or a recommendation.
- Changes to the ontology's types or edge types beyond reading direction (G1).
