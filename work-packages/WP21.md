## Purpose

Bring the release up to what the chat path's live run taught (`acceptance/chat-path/live-run-wp18-r4.md`; candidates
C1 to C8 in `work-packages/candidates.md`, all in v0.1 by D-102 and D-103). Separate the tool's **rules** (what
conformance requires, enforced by the tool) from the **norms** (guidance to coders and assistants, the same for a
person or an LLM, carried in docs and skill files). Make the chat path's session life cycle reproducible and secure,
and show the stricter "leave no trace" life cycle as one option. Words follow `GLOSSARY.md`; the terms this package
adds are listed under G9.

## Goals

- **WP21-G1. The edge table reads subject, predicate, object (C1).** The "Edges told" table's columns are
  `from | type | to | note`; each row reads as a sentence ("parents holds bike-safe-for-children"); every edge name
  reads from `from` to `to`. The layout contract states a skimmability requirement.
- **WP21-G2. Uncoded narratives are excluded, and say so (C2, the rule).** A narrative is **coded** when it links at
  least one node page anywhere in its body (a row end of its table, or a link in its account). An uncoded narrative
  is left out of the knowledge graph and every view and is reported as excluded by `check` and by the views; it is
  included as soon as it is coded. A link in the account is the conformant place for a node the narrative names with
  no edge (a lone node). A page-contract and catalogue change; it adds no type and no edge type.
- **WP21-G3. The norms, apart from the rules (C2 to C5).** One normative guide, separate from the rule catalogue,
  covering: the expected shape of a coded narrative (a coherent account and a set of nodes and edges, not necessarily
  connected, whose worth is in recurrence across narratives); links in the account (a "may"); descriptions (brief, not
  repeating the account; the error at `done` is intended, like a required commit message; an assistant may offer one);
  writing as a mixed loop, either side first, any number of rounds, with the coder's `done` as validation; and status
  set when the coder leaves a page (`done` or `draft`; nothing forces `draft`), with the fields `done` needs listed so
  a coder finishing a stub in one sitting knows them. C3 is met by norms: the catalogue's status row for `description`
  stays as it is.
- **WP21-G4. The norms as chat-path skill files (C6).** The assistant's rules and the norms ship as a skill package in
  the tools repo, with the edge grammar, `kind`, one loop step per reply, offering a description, and naming the pages
  to tag at the end of a session. The chat-path guide uses the chat's Skills and a saved agent (the chat's feature; the
  assistant is still the actor) and says how to start a chat with it.
- **WP21-G5. The session key is handled as a secret (C7).** A spike recommends how the launcher keeps the key (for
  example the macOS login keychain) so it is never in a process's arguments or a file others can read, and is on the
  clipboard only when the coder asks; the ACE decides and logs; then the launcher is built to it. Anything
  macOS-specific is isolated in the launcher and recorded (MISSION, Platforms). The life-cycle guide describes good
  security practice.
- **WP21-G6. The image; Colima the default (D-105, D-106).** CI builds the MCP server's image on every change to
  `deploy/` or the server and, at the release tag the ACE makes (MISSION, Release step 3), publishes it to the GitHub
  Container Registry under the tools repository. That push waits on the chief engineer's mission amendment to Release
  step 3 (proposed, not made); if he declines, there is no push and the launcher keeps building locally. The launcher
  pulls the image matching its version and builds locally only when none is published (so the candidate still works
  before release). A published image cannot carry the host's user id, so the launcher sets the user at run time,
  not at build time. The chat-path guide leads with Colima
  (v0.1 is Mac only); Docker Desktop is the untested alternative.
- **WP21-G7. The life cycle, and "leave no trace" as an option (C8, D-107).** The chat-path guide walks one session
  from start to clean-up. A separate walkthrough shows the "leave no trace" option for a strict data policy (an AI
  platform non-retention or "approved chatbot only" policy): a temporary chat; the field notes uploaded as a
  collection; the server entry, agents, prompts and skills set up for the session; and every one of them removed from
  the platform at the end, local copies kept. It says that this is one policy option, a MAY, not a recommendation.
- **WP21-G8. WP8-U1, carried (D-110).** The held fixes (`wp8/u1`: `stub` on an existing page of the same type is a
  no-op; `set-status done` reports the page's own check) ported onto `dev`, with exactly the two assertion changes
  D-110 allows in `tests/ops/test_ops_stub.py`.
- **WP21-G9. Words.** The glossary gains, as a logged call with the change consultant's sweep: coded and uncoded
  (narrative), excluded, rule and norm, skill (the chat's), saved agent (the chat's), session key, "leave no
  trace", the edge table ("Edges told"), and range vault. SCAT-MENTION, a link suggestion, leaves the default check and is offered behind an opt-in, like fingerprint
  candidates (D-101), so a "may" is not graded as a warning.

## Non-goals

- The live runs of the chat path (G4's loading in the chat, G7's walkthrough run, the chat-path UA-A): the chief
  engineer's sittings, as he pastes each key.
- Docker Desktop testing (withdrawn, D-105). Any platform but macOS for users.
- Making "leave no trace" a default or a recommendation.
- New node types or edge types; changing what an edge means. G1 changes column order and wording only.
- Publishing anything before the release tag.

## Definition of good

A coder can read any "Edges told" row as a sentence, knows from one page what the tool requires and what is only
guidance, and can run a chat-path session (any data policy, from relaxed to "leave no trace") from the docs alone,
with the key never exposed on their machine.

## Definition of good enough

WP21-R1 to R10 met, with R4's loading, R7's walkthrough run and R6's first push left to the chief engineer's sitting and
the release, each named in the reviewer's guide.

## Agent's defaults

- *(default)* "Coded" counts a link to a node page anywhere in the body, table row ends included.
- *(default)* SCAT-MENTION moves behind an opt-in (G9).
- *(default)* The registry is the GitHub Container Registry under the tools repository; the image is public, as the
  repository is.
- *(default)* The tool reads only the new table order; old tables get a fix message, not silent support.
- *(default)* The normative guide is one page, `docs/norms.md`.
