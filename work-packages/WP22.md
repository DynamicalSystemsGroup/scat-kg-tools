## Purpose

The leave-no-trace run (`acceptance/chat-path/leave-no-trace-run.md`) showed the launcher works but is not yet a
small, clear app: it silently reused a remembered vault (L1), it could not be found or minimised, and it does not say
what it is or what state it is in. The chief engineer: "basically its just a small local app that runs an mcp server.
let's package it up that way so its clear and easy to use" (C10, `work-packages/candidates.md`). This package makes
SCAT Chat that, and fixes the walkthrough steps the run found. Words follow `GLOSSARY.md`.

## Goals

- **WP22-G1. What it is and where it is.** SCAT Chat installs to Applications (the build puts it there, or the guide's
  one step does, with no terminal), and its window or menu says plainly that it runs the SCAT MCP server for the chat.
- **WP22-G2. Out of the way.** While a session runs, SCAT Chat does not sit in front of the coder's work: it can be
  minimised or lives in the menu bar, and can be brought back.
- **WP22-G3. Transparent state.** It shows the session's state at a glance (for example a coloured light: starting,
  running, stopped, a problem), the vault it is serving, and the address.
- **WP22-G4. The two things to paste.** "Copy address" beside "Copy key"; copying does not flicker the window.
- **WP22-G5. The vault is chosen, not assumed (L1).** At each start the coder sees which vault will be served and can
  change it without a terminal; a remembered vault is offered, never used silently.
- **WP22-G6. The walkthroughs match the chat as it is (L2 to L5, L8, L10).** Step 2 names SCAT Chat and where it is;
  the server form's required consent ("I trust this application") and header format are named; a Connect step and a
  check that the entry is connected are added; the skill form's required Description is named (from the file's own
  description); the skill file's HTML comments do not show as text in the chat; step 43 says why it is needed (a note
  attached to a temporary chat stays in the file library); an agent's tool must be added again after its server entry
  is deleted and re-added. In `docs/chat-path.md` and `docs/leave-no-trace.md`.

## Non-goals

- A signed or notarised app, an App Store build, or any platform but macOS.
- Changes to the MCP server's tools, the skill's rules (C11) or node-page help (C12, a spike first, D-123).
- The chat-path user tests (WP20-UC1) and a second leave-no-trace run: the chief engineer's sittings.

## Definition of good

The chief engineer opens SCAT Chat from Applications, sees what it is, which vault it serves and that it is running,
copies the address and the key, and puts it out of the way; nothing about it surprises him.

## Definition of good enough

WP22-R1 to R8 met, with R1, R2 and the visual parts of R3 to R5 confirmed in the chief engineer's next sitting and
named in the reviewer's guide.

## Agent's defaults

- *(default)* The spike recommends the mechanism; the ACE decides and logs; then build (ORG, new mechanism).
- *(default)* A remembered vault is offered as the default choice at each start, with "Choose another".
- *(default)* Installing to Applications is a copy the build or the guide does; nothing is installed system-wide.
