## Purpose

The chief engineer wants the assistant to help fill in node pages as a meaningful synthesis of each node as it appears across many narratives, avoiding naive term matching (C12, quoted in `work-packages/candidates.md`).
RS4 (`research/node-pages/readout.md`) found how, on the range vault, and recommended two packages; both are in v0.1
(D-136). This package builds them: A first, then B. Words follow `GLOSSARY.md`.

## Goals

- **WP24-G1. Evidence for one node (A1).** A view, `scat evidence <node>` (CLI, Python and MCP), returns every
  narrative that links the node, the whole paragraph around each link with the linking sentence marked, its edges with
  the narratives that tell them, and its adjacent nodes (one edge away in the four layers). Writes nothing. It never
  reads contributor pages or `attributed_to`.
- **WP24-G2. What a node page holds (A2).** The norms page gains a section, "What a node page holds", that says what a node page holds, by type, in four parts (what it is;
  how the narratives tell it; where accounts differ; what is thin), written across narratives and citing them, never
  pasting one account. A view reports how much of a node page's text repeats a narrative's (the copy-share RS4 used).
- **WP24-G3. A drafted node page (A3).** An MCP prompt and the skill let the assistant draft one node page from the
  evidence for the coder to accept or edit (the coder writes it into the vault, as for a narrative's account); a sweep
  workflow walks the stub pages in turn, one page per step.
- **WP24-G4. Possible duplicates (B1).** A review view proposes pairs of node pages that may be one node (synonyms),
  from structure (shared edges and narratives, adjacent nodes, description reuse), never from matching names; the coder
  decides. Proposing pages that may hold two nodes (homonyms) waits on a short spike on the G6 vault (RS4 found no
  structural method for it) and the ACE's logged decision after it; until then the view covers synonyms only.
- **WP24-G5. Merge (B2, B3; MISSION G4).** A tool operation `merge <a> into <b>` for two node pages of the same type,
  by CLI and Python first (R-19), with a plan shown first (`--plan`); then every link to `a` in the four layers and the
  narratives is rewritten to `b`, `a`'s body is appended to `b` under a heading naming `a`, `a`'s description is dropped
  (`b`'s is kept), `a` is removed, `b`'s status is unchanged, and the index pages are regenerated. If the merge would
  make a duplicate row, it refuses and writes nothing. Narratives already `done` stay `done`; the result lists every
  `done` narrative it changed (D-136). It refuses a cross-type pair, a contributor page as `a` or `b`, and any
  contributor page whose body links `a` (listed, unwritten). Split is a plan only: it names what the coder must re-link.
  Through MCP the assistant may show the plan; applying a merge is refused, as `set_status` refuses `done`.
- **WP24-G7. The assistant's rules for node pages.** `contracts/assistant.md`, the skill and the server's rules text
  change identically: the assistant SHALL NOT write a node page's body through the tool; it MAY draft one as text for
  the coder; it MAY show a merge plan and SHALL NOT apply a merge; the operations and views lists (A3, A4) gain
  `evidence`, the review view and the merge plan.
- **WP24-G6. Tried.** Cold users try A on a vault with more narratives per node than the range vault holds.

Every new view and `merge` carries the vault's attribution mode on its result, as every result does since WP23.
Candidates: WP24 takes C12; C14 and C15 (WP25) share `docs/coding.md`, so WP24 edits only its node-page lines there.

## Non-goals

- The assistant writing node-page text into the vault, or running a merge (A8 and the coder's authority hold).
- Name or string matching to find synonyms.
- Automatic splitting.

## Definition of good

A coder opens a stub node page, sees in one view everything the vault says of that node, accepts or edits a drafted
synthesis, and can fold two pages that name one node into one, with a plan first and nothing done they did not choose.

## Definition of good enough

WP24-R1 to R7 met.

## Agent's defaults

- *(default)* A before B in one package; B's units start when A's have landed.
- *(default)* The test vault for G6 is built from the range vault plus synthetic narratives, lab material only, in
  three copies, one per attribution mode.
- *(default)* `merge` is an operation of the tool like `record-edge` (machine interface, CLI, Python, MCP), with a
  `--plan` dry run.
