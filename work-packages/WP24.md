## Purpose

The chief engineer wants the assistant to help fill in node pages as "a meaningful synthesis of the named concepts as
they appear across many narratives", avoiding naive term matching (C12, quoted in `work-packages/candidates.md`).
RS4 (`research/node-pages/readout.md`) found how, on the range vault, and recommended two packages; both are in v0.1
(D-136). This package builds them: A first, then B. Words follow `GLOSSARY.md`.

## Goals

- **WP24-G1. Evidence for one node (A1).** A view, `scat evidence <node>` (CLI, Python and MCP), returns every
  narrative that links the node, the whole paragraph around each link with the linking sentence marked, its edges with
  the narratives that tell them, and its neighbours. Writes nothing.
- **WP24-G2. What a node page holds (A2).** The norms say what a node page holds, by type, in four parts (what it is;
  how the narratives tell it; where accounts differ; what is thin), written across narratives and citing them, never
  pasting one account. A view reports how much of a node page's text repeats a narrative's (the copy-share RS4 used).
- **WP24-G3. A drafted node page (A3).** An MCP prompt and the skill let the assistant draft one node page from the
  evidence for the coder to accept or edit (the coder writes it into the vault, as for a narrative's account); a sweep
  workflow walks the stub pages in turn, one page per step.
- **WP24-G4. Candidates for one concept or two (B1).** A review view proposes pairs that may be one concept (synonyms)
  and pages that may hold two (homonyms), from structure (shared edges and narratives, neighbours, description reuse),
  never from matching names; the coder decides.
- **WP24-G5. Merge (B2, B3).** A tool operation `merge <a> into <b>` for two node pages of the same type: a dry-run plan
  first; then every link to `a` is rewritten to `b`, `a` is removed, and the vault stays conformant (duplicate rows are
  caught as today). Narratives already `done` stay `done`; the result lists every `done` narrative it changed (D-136).
  Cross-type merges are refused. Split is a plan only (it names what the coder must re-link). The assistant may propose
  a merge and show the plan; the coder runs it.
- **WP24-G6. Tried.** Cold users try A on a vault with more narratives per node than the range vault holds.

## Non-goals

- The assistant writing node-page text into the vault, or running a merge (A8 and the coder's authority hold).
- Name or string matching to find synonyms.
- Automatic splitting.
