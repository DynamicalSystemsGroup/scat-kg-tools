## Purpose

Lock in the lifecycle model the tools and skills will be organised by (D-157, D-162). The chief engineer: "a small
finite state machine where each state is a stage, and each stage has a narrower set of expected inputs, outputs, tools
and skills that keep the agent on track. predicates help detect or request state-transistions (changes to stage). this
should be an as simple as possible but no simpler formal model which gets a concrete instance". Knowing the stage
"will alter what tools and skills are exposed, as well as what data is treated as required inputs and what kinds of
data it can produce as output. these are enabling constraints". Words follow `GLOSSARY.md`.

## Goals

- **WP29-G1. The formal model.** The smallest form that holds: a finite set of stages; per stage its required inputs,
  allowed outputs, tools, prompts and skills; transitions, forward and backward, each with its predicate (detect or
  request), trigger and who decides; the unknown stage and how it is resolved.
- **WP29-G2. The concrete instance for SCAT.** The model filled in for SCAT's lifecycle: its stages (from the flow's
  steps and the coding loop), each stage's inputs, outputs, tools, prompts and skill sections, and every transition,
  including the backward moves the flow gives (Analyse to Code; `done` to `draft`) and those the 27 November runs
  showed (Code to Plan when the cap is met, then to the setup person).
- **WP29-G3. How stage travels and how the server answers.** The chosen way for a request to carry stage (for example
  a header, as the chief engineer suggested), what the server does with an unknown stage (a result asking for
  clarification), and what it does with a call outside the stage, chosen from RS5's options.
- **WP29-G4. The glossary.** **Stage** and **transition** (and any other new word) in `GLOSSARY.md` and the terms page.

## Non-goals

- Implementing it (WP30).
- The assistant's habits (WP31).
- Changing the ontology, the page contracts or the views.

## Definition of good enough

WP29-R1 to R6 met.

## Definition of good

A coder, an assistant and a reviewer can each say, from the document alone, what stage a session is in, what may happen
there, and how to move to another stage.

## Agent's defaults

- *(default)* The instance is kept as data (a YAML block in the document) that the consistency test and WP30 read, so
  the model and the code cannot drift.
- *(default)* The diagram is generated from that data, not drawn by hand.
- *(default)* A fresh reviewer reads the document before it goes to the chief engineer.
