## Purpose

Before the chief engineer's hands-on walkthrough, find and fix what a reader would trip on: wording that echoes how he
explained something to the agents ("prompt residue", D-139: "literal or verbatim translations of prompts"), and gaps in
clarity, concision and agreement between the docs and the code, found by AI user tests on both paths. Words follow
`GLOSSARY.md`.

## Goals

- **WP26-G1. The sweep.** Every page a coder sees (the docs site, the template's README and pages, SCAT Chat's
  messages, the skill text, the CLI's help and messages) is read for prompt residue and rewritten for the reader:
  deontic keywords outside the assistant's rules and the catalogue's mode rule; meta-talk about options and
  recommendations beyond one plain line; quoted instruction phrasing; decision-log language ("as decided", log numbers)
  in user pages; design-conversation asides. Also **test and work status** in user pages ("what has and has not been tried", "untested",
  "the lab run of ...", "not recorded", "nobody has yet run"): it moves to the test plans and the reviewer's guide, and
  the page says only what a coder needs to act (for example, which runtime to use and what to do if a step fails).
- **WP26-G2. The loops.** Rounds of AI user tests (UA-A personas: the by-hand path's p1 to p3 (UA-A's "manual path") and the chat
  path's c1 to c3 for the stages that need no live chat, key or sign-in: `acceptance/chat-path/plan.md` Sitting A (J1
  to J4) and J6; the other chat stages stay for the chief engineer's sitting), each round
  fixed before the next, until a round finds no blocking finding and every finding is dispositioned.
- **WP26-G3. Docs and code agree.** Every command, message, field, file name and option a page quotes is checked against
  the code by a test or a reviewer's run, and every mismatch is fixed on one side.

- **WP26-G4. Items carried in.** From D-141: the chat-path cold readers' unexplained jargon, step 28's two actions,
  "Colima left running" beside "nothing left running", ordered lists restarting per section. From D-143 and D-150: the
  stale "stays 2" in `impact/WP24.md` and its no-op `\b` grep; "(D-020)" in the template's example pages and the two
  reference samples that quote them. From D-153: the 13 status lines WP25's test allows (remove them and the allowance);
  a glossary entry for **timeframe** (a logged call); the Docker Desktop box in `docs/chat-path.md` and its pin in
  `tests/docs/test_chat_guides.py`.

Candidates: WP26 takes none. C7 (the session key in the process list) was fixed by WP21-U8 (D-115) and is marked
taken; WP26 touches `deploy/` only for message wording.

## Non-goals

- New features or new pages beyond what a finding needs.
- The chief engineer's walkthrough (UA-M) and his chat-path sitting.

## Contracts

CLI, MCP and launcher message wording may change where the sweep finds residue; operations, fields and schema versions
do not (R-22). The contract tests' word caps (the terms page 910, the machine-schema page 646, the interface page 774)
may rise only by a logged ACE call, as before.

## Definition of good enough

WP26-R1 to R4 met; the reviewer's guide lists what only the chief engineer's sitting can confirm.

## Definition of good

A coder reads every page as written for them: plain, short, true to what the tools do, with nothing about how the
project was built or tested; testers on both paths finish with no blocking finding.

## Agent's defaults

- *(default)* At most three rounds; a fourth only if a blocking finding remains.
- *(default)* Chat-path testers run only the parts that need no live chat; the live chat parts stay for his sitting.

## Blast radius

`docs/`, `mkdocs.yml`, `docs/assets/`, `skills/` and `contracts/assistant.md` (the drift test follows), `deploy/` and
`src/scat_kg/` message and help strings only, `tests/`, `acceptance/`, `work-packages/impact/`, `GLOSSARY.md`, the
template (on `wp26/template`), `decisions/log.md`, the board and metrics. Not `pyproject.toml`, `uv.lock`, or the
ontology's meaning.
