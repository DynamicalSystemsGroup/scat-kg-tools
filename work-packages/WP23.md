## Purpose

`MISSION.md` (Non-goals, as edited by D-127) now says a vault runs in exactly one **attribution mode**, set by the
organiser at set-up and known to the tools: attribution **required**, **optional** or **disallowed** (the Chatham
House rule); the modes are disjoint and must not bleed together in use; edges and nodes always record groups. The
chief engineer's pilot uses the disallowed mode, and he wants the other two in the software. This package builds the
modes, and renames the TBox's `scat:Attributes` so that "attribution" means only this. Words follow `GLOSSARY.md`; the
terms it adds are under G6.

## Goals

- **WP23-G1. The mode is declared, and known.** Each vault declares its attribution mode in `scat.toml`; the tools read
  it before anything else and report it; a vault with no mode, or an unknown one, is refused by the check with a fix
  that names the three choices. The template declares `disallowed`, with one line saying how to choose another.
- **WP23-G2. Attribution, where allowed.** A narrative may name the people it is attributed to in one field,
  `attributed_to` (as the organiser records them; never a node, never a link). In **required** mode a `done` narrative
  must name at least one (a warning before `done`, like other fields `done` needs); in **optional** mode it may; in
  **disallowed** mode the field is an error at every status. The field is optional in the TBox; the per-mode rules live
  in the checks.
- **WP23-G3. No bleeding.** An attribution never enters the knowledge graph's nodes or edges or any view (fingerprint,
  edge tables, layered view, trace, exports). A vault whose mode is changed is checked as a whole against the new mode,
  so a switch to `disallowed` flags every page that still names an attribution. The machine interface is not a view:
  it carries the mode on every result, and a narrative's `attributed_to` only in the check's page record and only where
  the mode allows.
- **WP23-G4. The assistant respects the mode.** The MCP server reports the mode on every result (no MCP tool writes
  fields other than status, so none can write an attribution); the skill tells the assistant to read the mode and never
  to draft a person's name into a page or the account in `disallowed` mode.
- **WP23-G5. Set-up and expectations.** The planning guide's set-up stage has the organiser choose the mode and say
  what participants are told; the consent page names the three modes; the coding guide shows the field.
- **WP23-G6. Words and the formal name.** The TBox's `scat:Attributes` (affordance to technology, label "is provided
  by") is renamed to a name for "is provided by" everywhere; the glossary gains **attribution mode** and
  **attribution** (the people a narrative is attributed to, where the mode allows; not the participants in general,
  whom the mission and glossary call contributors) as a logged call with the change consultant's sweep. The ontology's
  `owl:versionInfo` moves from 0.2.0 to 0.3.0 (the published IRI is `https://w3id.org/scat#`).

Candidates: WP23 takes C13. It leaves C11, which shares `SKILL.md` (WP23 edits the skill only after WP22-U2), and
C9, C12 untouched.

## Non-goals

- Attribution of edges, nodes or quotations to individuals. Contributors are a narrative's metadata only.
- Detecting personal names in a narrative's text (the tool cannot; the norms say what the organiser does).
- Identity management, consent records or contact details for contributors.
- The chat-path launcher and its guides (WP22).

## Definition of good

An organiser chooses one of three modes at set-up, tells participants what it means, and can rely on the tools never
to let a contributor's name appear where the mode forbids it, nor in the knowledge graph at all.

## Definition of good enough

WP23-R1 to R8 met.

## Agent's defaults

- *(default)* The `scat.toml` key is `attribution`, with values `required`, `optional`, `disallowed`; the narrative field
  is `attributed_to`, a list of strings.
- *(default)* A missing mode is an error (the system must know the mode), not a silent default; the template ships
  `disallowed`.
- *(default)* An attribution is not a linked page and not a node; the TBox gains one optional narrative field for it,
  separate from the edge types (the ontology research's `prov:wasAttributedTo` sense); logged as D-128.
- *(default)* Pin order, so `dev` never goes red: the tools units merge to an integration branch; the template branch
  pins that integration commit and declares its mode; the integration branch lands on `dev` together with
  `TEMPLATE_COMMIT` pointing at the template commit; then the template's `dev` takes its branch. The test fixtures that
  write `scat.toml` (27 files, through the three helpers) default the mode in the helpers.
- *(default)* The new name for the edge property is `scat:ProvidedBy`.
