## Purpose

The chief engineer: "any figure generated can be matched with a set of tables containing explicit nodes and edges";
"it's also worth ensuring every image we can generate has an associated data dump method that returns its nodes and
edges which could be viewed as a table"; and, on this scope: "we may have overlooked a layer. in practice we need the
query process, then the query result feeds both the plot and the table. this way we can have one, the other or both,
with guaranteed consistency if the query is the same". Asked how the server should offer it: "One tool per view".
Today `draw.fingerprint(...)` runs the view's query again inside itself, and the server has two tool families
(`fingerprint`, `draw_fingerprint`, and the same for layered and trace), each running its own query; in the runs the
assistant gave a table without the plot, and on inference.coop the model receives nothing from a PNG.

## Goals

- **WP33-G1. The query is its own layer.** A view's query returns a result (nodes, edges and the view's other data);
  rendering never re-runs it. The plot renderer (PNG or SVG) and the table renderer each take a query result.
- **WP33-G2. One tool per view on the server.** `fingerprint`, `layered` and `trace` each take `output` (table, plot or
  both) and, for a plot, `format` (png or svg); one call runs the query once and renders what was asked. The
  `draw_fingerprint`, `draw_layered` and `draw_trace` tools are folded in and retired.
- **WP33-G3. Consistency by construction.** A test holds that, for the same query result, the plot's drawn nodes and
  edges equal the table's; and that any view with a plot has a table.

## Non-goals

- New views, or changing what a view's data contains.
- The CLI's commands (`scat fingerprint`, `scat draw …`) keep their names and output.
- What the assistant says about figures (WP31).

## Contracts

The MCP interface changes: the three view tools gain `output` and `format`; the three `draw_*` tools are retired (a
removal, listed in the reference's changes). The machine-interface schema gains the view tools' new arguments. The
Python API: `draw` gains a render-from-result entry; the existing `draw.fingerprint(...)` and the others stay as
conveniences that run the query and render once.

## Definition of good enough

WP33-R1 to R6 met.

## Definition of good

A coder or an assistant asks one question of the vault and gets the picture, the table or both, always in agreement.

## Agent's defaults

- *(default)* `output` defaults to table, so a caller that asks nothing gets what the view tools return today.
- *(default)* In `both`, the plot comes first, then the table as structured text in the view's document form.
- *(default)* The tool count drops from 22 to 19; pages that state the count follow.
