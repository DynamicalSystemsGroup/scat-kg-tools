## Purpose

The chief engineer: "any figure generated can be matched with a set of tables containing explicit nodes and edges",
and "it's also worth ensuring every image we can generate has an associated data dump method that returns its nodes and
edges which could be viewed as a table". Each drawing already has its view, but the server returns a picture or a table,
never both, so the assistant gave one without the other; and on inference.coop the model receives nothing from a PNG
(`acceptance/walkthroughs/analysis-session-inference-coop.md`).

## Goals

- **WP33-G1.** Each of the server's drawing tools returns, in one result, the drawing and the drawing's nodes and edges
  (the same data its view returns), so the person sees the picture and the model can read exactly what is drawn.
- **WP33-G2.** A test holds every drawing to having its table twin: any drawing added later fails the test without one.

## Non-goals

- New views or changes to view data; the CLI and Python drawings (they already have `views.*` twins).
- What the assistant says about a figure (WP31).

## Contracts

The drawing tools' results gain the nodes-and-edges content beside the image; the tools' names, arguments and the other
tools do not change. `docs/reference/mcp.md` follows.

| WP33-R3 | CI green; `check_metrics.py --accept WP33` passes. | CI; the check |

## Definition of good enough

WP33-R1 to R3 met.

## Definition of good

Whatever chat a coder uses, a figure and its explicit nodes and edges arrive together.

## Agent's defaults

- *(default)* The table goes as structured text content after the image content, in the view's own document form.
- *(default)* With `format` svg the result is the SVG text plus the same table.
