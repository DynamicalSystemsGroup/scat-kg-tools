## Purpose

Build the chat path of `MISSION.md` G14 on the route RS3 proved (D-084, D-090): the MCP server (M8) as a front end to
the tool, run by the coder on their own Mac in a read-only container, published through a tunnel with an API key, and
used from the inference.coop chat, with no terminal for the coder. Words follow `GLOSSARY.md`; modules follow
`contracts/architecture.md`.

## Goals

- **WP18-G1. The MCP server (M8)** in `scat-kg`, as an optional extra: tools that call the tool's operations and
  return their machine-interface data (check, status, stub, record and remove an edge, the views from M6), and prompts
  and skills for the coding loop. It holds no authority: it never sets a narrative to `done` (the coder's act), and it
  writes only through the tool's operations. Key-gated over streamable HTTP.
- **WP18-G2. The assistant's file**: one short file under `contracts/` stating what the assistant may and may not do,
  cited by the MCP prompts, the IDE setup skill and the docs (architecture, actors and authorities).
- **WP18-G3. The container and the launcher**: an image of the server; a launcher the coder starts without typing a
  command, which starts the container with the vault mounted, publishes it through the tunnel, shows the URL and a
  fresh key to paste, and on stop tears everything down and rotates the key. It handles RS3's findings: a vault under
  `~/Documents` that the container runtime cannot read, the tunnel's one-time HTTPS and Funnel settings, and the
  neutral machine name before HTTPS. If the coder's machine needs a container runtime and a tunnel app first, their
  installation is documented with their graphical installers.
- **WP18-G4. Docs**: the chat-path guide (set up once, start a session, the coding loop in the chat and in Obsidian,
  views, lock a version, stop), and the IDE note with the setup skill in the template (D-3).
- **WP18-G5. Tests**: the MCP tools against the lab vault locally (R-20's automated part), including the key gate and
  the refusals; the launcher's start and teardown.

## Non-goals

- The range vault (WP19); hosting on governed compute (after v0.1, D-084).
- Testing other providers; any change to what the graph means.
- Live use of inference.coop by agents other than the ACE, and any heavy use: live runs are few, human-paced, with lab
  material, and each ends torn down with its key rotated.

## Definition of good

A coder who has never opened a terminal sets up once from the guide, starts a session, codes a narrative with the
assistant's help in the chat and in Obsidian, and stops, leaving nothing running.

## Definition of good enough

WP18-R1 to R6 met.
